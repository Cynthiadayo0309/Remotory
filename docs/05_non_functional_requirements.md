# 05. 非機能要件

## 性能

- 企業一覧はページ単位 / 追加読み込み
- 全企業データをブラウザへ一括取得しない
- 検索条件で使う列へINDEXを付ける
- 管理者の一括確認でD1へ大量同時書き込みしない
- 外部サイト確認は非同期 / 長時間処理としてWebリクエストから分離する

## D1方針

Remotoryは読み込み中心。

一般ユーザーによる高頻度書き込みはMVPではない。

D1書き込み用途:

- 管理者登録 / 編集
- 最終確認日更新
- 自動確認履歴
- 変更候補

将来のお気に入り / 保存検索も低頻度書き込みを想定。

閲覧履歴は実装しない。

## セキュリティ

### 管理画面

- `/admin/*` 認証必須
- 管理APIもサーバー側認証必須
- URLを知っているだけでは操作できないこと

### DB

- SQLバインド
- 入力値検証
- 直接SQL文字列連結を避ける

### Secrets

- Gitへコミットしない
- Cloudflare Secrets / 環境変数で管理

### SSRF

外部ページ取得機能では必須。

- http / https のみ
- private IP拒否
- localhost拒否
- link-local拒否
- リダイレクト先もチェック
- タイムアウト
- 最大レスポンスサイズ
- リトライ上限

## SEO

MVPで実施。

- 各企業に `slug`
- `/companies/[slug]`
- title
- description
- canonical
- OGP
- sitemap
- robots.txt

検索 / filter query ページを大量indexさせない。

## アクセシビリティ

- keyboard
- focus
- label
- aria
- contrast
- 色だけで状態を伝えない

## エラー表示

ユーザー / 管理者向け表示は分かりやすい日本語。

内部エラーコードはログで保持可能。

## ログ

最低限記録:

- 更新開始 / 終了
- 対象企業
- fetch 成功 / 失敗
- AI利用
- 変更候補作成
- 承認 / 却下

一般ユーザーの閲覧履歴はD1へ保存しない。

## テスト

Unit:

- 判定変換
- validation
- DB repository
- 差分生成
- URL安全性

Integration:

- D1 CRUD
- 変更候補承認

E2E:

- 企業検索
- 企業詳細
- 管理画面認証
- 企業登録 / 編集
- 自動確認の主要フロー
- 承認 / 却下
